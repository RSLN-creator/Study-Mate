# 闭卷检验怎么到达学生手上

「考考我」那套产物（卷子 / 判分键 / 背默卡）落在科目的 `assessments/`。**阅读端不认识这个目录**——
它只列 `reference/` 里的 `.md` 与课件。于是学生要拿卷子，只能由总控把路径贴给他，或自己去翻文件。

这条 ADR 记的是「为什么不顺手把它放进 `reference/`」，以及以后要改时该往哪儿改。

## 面临的问题

想让卷子出现在阅读端的「参考资料」里，最省事的做法是把它拷进 `reference/`。

**2026-11-15 我这么做了，拷的是卷子、判分键、背默卡三份。拷完才发现：判分键里有全部答案，
背默卡第 4 节的要点表是 S1 的尺子。**

而且泄得悄无声息——学生打开「参考资料」，答案就列在那里，没有任何提示说「这份不该看」。
判分键开头那句「评卷前不要打开」，靠的是自律，不是权限。

**立即撤销，并加了一条守卫**（`test_no_answer_leak`）：阅读端可读的目录里出现文件名叫
「判分键」或「背默卡」的，直接红。守卫做过实测——真拷一份过去，它当场报错。

## 决定：现在**不改**阅读端

- **`assessments/` 不可读，这是判分键唯一的防线**，不改。
- 卷子与卡**只能由总控在会话里给路径**，或学生自己去翻文件。这是当前形态，接受。
- **`reference/` 里不许放判分键、不许放背默卡**（要点表就是答案）。卷子本身不含要点表，
  理论上可以放——但**这一版也不放**：卷子与判分键是一对，只放进一半，学生会以为「参考资料里
  那份就是全部」，然后找不到判分键。

## Considered Options

- **把 `assessments/` 加进阅读端**（第四个可读目录）：最省学生的事。代价是判分键必须与卷子
  分目录放，而且要做「谁有权看判分键」的权限——这在单机单用户的当下没有意义，在真要多人的
  时候才值得做。**这一版不做。**
- **把卷子放进 `reference/`、判分键留在 `assessments/`**：卷子能一键打开。代价是一对产物被
  拆到两个地方，`文件归属` 要写两行维护者，而且学生点开「参考资料」看到一份没有答案的卷子，
  会去问「怎么判」。**这一版不做。**
- **维持现状，由总控贴路径**：学生多一步操作。但这正是「检验是他自己要做的」这件事的一部分
  ——**他不是被推去做卷子的，是他主动要的**。这一版采用。

## Consequences

- 学生要做闭卷检验，得由总控给路径，或自己翻 `assessments/`。
- **`reference/` 的语义保持干净**：那里只放学习资料，不放任何「带答案的检验」。
- 以后要做「一键开卷」，正确的位置是**给阅读端加第四个可读目录 + 一份「这份能不能给学生看」
  的标记**，不是把文件挪进 `reference/` 蒙混过去。
- 那条守卫会在任何人下次想「顺手拷过去」时拦住他——**包括我自己**。
