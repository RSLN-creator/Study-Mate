# 阅读端可写「读完」那一步进度

学生把一课**读到末尾**，该节点就是「已学完」——阅读端直接写 `progress.yaml` 的
`nodes.<节点id>.status`（普通节点；`kind: 实验` 不动），不必绕回会话让总控转述。这是阅读端写学习数据的
**第三处、也是最后一处**（前两处见 [ADR-0010](0010-阅读端可直接写参考资料.md) 与 [ADR-0007](0007-作答数据与题库分离.md)）。

## 背景：为什么原来「读完也永远显示正在学」

那是**规则明文封顶**，不是 bug：`learning-system` 第 5 步要求不是验收点就不派评估、按"读了 + 页内自测做了 +
实操断言全绿"给一个**最多到「学习中」**的更新；`lib/core/rules.ts` 里能升到「已学完」的路只有
`证据通过`（且必须独立证据）+ 实验课验收。而普通节点没有验收点，于是"这一课我读完了"这个事实永远表达不出来。

## 决定

- **纯函数域加一个推进事件 `读完`**（`lib/core/rules.ts` 的 `ProgressEvent`）：未开始 / 学习中 → 已学完；
  已学完不动。它**不在** `NON_INDEPENDENT_EVIDENCE` 那份排除清单里——那份清单管的是 `证据通过` 的资格，
  而 `读完` 是另一条并列的路（事实，不要求证据）。**`要求复习` 仍是唯一的回退口**，`证据通过` 的语义一个字没动。
- **宿主侧新增 `POST /api/studymate/progress`**（`lib/progress.ts` + `lib/progress-route.ts`），落点是
  科目目录下 `progress.yaml` 的 `nodes.<节点id>.status`；**别的键一个都不碰**（`notes`、别的节点、
  `project`、注释、行序、换行风格全部保形——写回是文本手术，不是"解析成对象再序列化"）。
- **并发保护沿用 `reference/` 与 `attempts/` 那两件武器**（判据在 `lib/core/fence.ts`）：幂等
  （`operationId` 重放回原回执）+ 版本号（`expectedVersion` 对不上就 409 拒绝并重读）。
- **`kind: 实验` 的课不在这条路上**：它仍只按验收结论置位（否则读完说明页就等于跳过了实验）。
  这条判据在数据层（读 `curriculum.yaml` 的 `kind`），不在客户端。
- **只认 `event: "读完"`**：别的值按「不认识的输入」拒绝（这条路不是通用进度写入口）。

### 契约（与阅读端约定的形状）

```text
POST /api/studymate/progress
请求体：{ subject, node, event: "读完", operationId, expectedVersion }
成功：  { ok: true, node, tier, changed, reason, version, progress }
拒绝：  { ok: false, status, error: { code, message }, version? }   ← 唯一错误信封（lib/route-envelope.ts）
```

- `version`：`progress.yaml` **内容**的 sha256 前 16 位（与 `attempts/` 同一口径：文件是我们与 agent 写的，
  内容自证最准；掺 mtime 会因为备份/同步假冲突）。读侧从 payload 的 `subject.progress_version` 拿它
  （`lib/library.ts` 已挂上），写回时原样当 `expectedVersion` 带上来。
- `changed: false` 的两种情形（已经「已学完」/ `kind: 实验`）**一个字节都不写**，只回当前版本号。
- `progress`：`progress.yaml` 相对**工作区**的路径（`.learning/subjects/<slug>/progress.yaml`）。
- 新码：`event-invalid` / `progress-missing` / `progress-invalid`（都进 `ROUTE_ERROR_CODES` 那份唯一词表）。

## Considered Options

- **让总控在会话里置位**（学生回会话说一句"学完了"，总控写盘）：不动架构，但总控在这件事上没有判断可做，
  纯粹是转述一句已知事实；而"读到末尾"这件事会话里根本拿不到，只有学生自述——那又退回成自评。
- **打开课件就算**（进门即「已学完」）：阅读端同样看得见，且更省事；但"打开过"不等于"读完"
  （`仅浏览过` 在证据资格里明确不算），进门置位会把整张进度表刷成学完。
- **停在「学习中」等自评或验收**：就是现状。普通节点没有验收点，代价是这个状态永远没有出口——
  正是本 ADR 要修的那件事。

## Consequences

- 阅读端能写学习数据的位置从两处变**三处**（`reference/`、作答数据、`nodes.<节点id>.status`）。
  ADR-0010 末句「下一个想改进度的人，答案是不行」对**进度这一个字段**不再成立，对大纲、课件、题库、档案
  仍然成立；ADR-0010 已补一条后续指针。
- **「已学完」在普通节点上不再表示"考过"，只表示"读完了"**。要判断真会不会，仍走实验课验收——
  `evidence-check` 的资格清单（独立证据、排除自评/同日重试/关键词标签/仅浏览过）管的是那条线，一个字没动。
  页内自测做没做、对不对也不拦（同一口径）。
- 客户端那侧要能拿到版本号：payload 的科目级 `subject.progress_version`（`lib/library.ts`）。
- **`updated_at` 不跟着动**：这一版只改 `status`。「接着上次」的主卡按 `updated_at` 的字典序最大值挑科目，
  所以读完不改变主卡的排序——这是**已知取舍**（改它要顺带定"谁的时间戳"，留待需要时单独决定）。
- 导出产物（离线页面）是只读的：`POST /api/studymate/progress` 与作答、资料一样明确回 403，
  不假装写了盘（`lib/export/page.ts`）。

## 与既有 ADR 的关系

- **[ADR-0010](0010-阅读端可直接写参考资料.md)**（阅读端可写参考资料）：它开了先例并写死"想改进度？不行"。
  本 ADR 按它自己给的理由（**需要判断的才不行**）把这句话收窄：读到哪里是事实，不需要判断，所以行。
- **[ADR-0006](0006-删掉阶段评估.md)**（删掉阶段评估）：普通节点的「已学完」本来就由学生这一侧驱动
  （那里写作"自评驱动"）。本 ADR 把驱动从"自评"改成"读到末尾这一事实"——没有新增任何第三方判断。
- **[ADR-0004](0004-学习数据格式冻结与例外.md)**（学习数据格式冻结与例外）：布局、文件名与 schema 全都不动，
  写的是 `progress.schema.json` 里本来就有的字段，冻结承诺原样成立。
- **[ADR-0007](0007-作答数据与题库分离.md)**（作答数据与题库分离）：同一种并发保护（幂等 + 版本号），
  实现共用 `lib/core/fence.ts`；同样只增不改（题库、课件、别的节点都不碰）。
